<objective>
Implement the Streamlit application shell, session state management, reusable UI component library, and the decoupled services and views for Page 1 (Overview), Page 2 (Event Explorer), and Page 10 (Settings & DB Health).
</objective>

<execution_context>
This plan runs as Wave 1 of Phase 8. It establishes the UI foundation, session state management, reusable styling components, and decoupled service architecture consumed by subsequent forensic pages.
</execution_context>

<context>
- Requirement UI-01 demands a multi-page Streamlit application structure separating presentation logic from detection services.
- Requirement UI-02 demands an Overview dashboard summarizing import jobs, total events, alert counts by severity, and threat breakdown.
- Requirement UI-03 demands an Event Explorer with multi-field filtering and tabular/JSON record inspection.
- Decision D-01 establishes that presentation logic is backed by pure Python services in `app/ui/services/` that are 100% testable via unit tests.
</context>

<description>
1. `app/ui/services/overview_service.py`:
   - `class OverviewService`:
     - `get_kpis() -> dict[str, Any]`: Total events, total alerts, critical/high/medium/low counts, active incidents, total imported files.
     - `get_severity_breakdown() -> dict[str, int]`: Distribution of alerts by severity.
     - `get_mitre_breakdown() -> list[dict[str, Any]]`: Top MITRE tactics and techniques represented in alerts.
     - `get_top_targeted_hosts(limit: int = 5) -> list[dict[str, Any]]`: Hosts with highest alert density.
     - `get_recent_critical_alerts(limit: int = 5) -> list[dict[str, Any]]`: Latest high/critical alerts.
2. `app/ui/services/event_explorer_service.py`:
   - `class EventExplorerService`:
     - `filter_events(...) -> tuple[list[dict[str, Any]], int]`: Multi-field filter (event_id, computer, user, image, time range, limit, offset), returns page items and total count.
     - `get_event_detail(event_id: int) -> dict[str, Any]`: Complete normalized record + raw payload.
3. `app/ui/services/settings_service.py`:
   - `class SettingsService`:
     - `get_system_health() -> dict[str, Any]`: DB file size, table row counts, SQLite version, rule directory status.
     - `get_active_config() -> dict[str, Any]`: Correlation sliding window minutes, rules path.
4. Create comprehensive unit tests in `tests/unit/ui/`:
   - `test_overview_service.py`
   - `test_event_explorer_service.py`
   - `test_settings_service.py`
</description>
